#Security and the data we store

Last updated: November 11, 2026

No empty promises. This page says what Caesar stores, where, and also what it does not protect.

01What is stored on your computer

Everything you use in the app lives on your computer.

WhereWhatEncrypted?
App localStorageOpen requests (headers, body and credentials you type), collections, variables, preferences and first-time flagNo, plain text
datos.json file (+ .bak when remote data is downloaded, .tmp while writing) in the app data folderA copy of your dataNo, plain text
Exports and importsOnly where you chooseDepends on what you choose
Operating system keychainAES-256 data key (32 random bytes) and Firebase session token (refresh token)Protected by the OS keychain

Important limitation. Variables may contain secrets and everything is stored in plain text on your computer. Anyone with access to your user account or disk can read it. We recommend disk encryption (FileVault, BitLocker, LUKS).

The data key is never written to disk or shown in the interface. The GitHub token is not stored. Signing out deletes the token from the keychain; deleting the account does too, but it does not delete local data or the data key.

The interface makes no network calls: everything goes through the Rust core. There is no analytics, telemetry, tracking cookies or crash reporting. In guest mode nothing is sent to any server of ours.

04End-to-end encryption

  • Algorithm: AES-256-GCM, with a random 12-byte nonce per message and the uid as authenticated data.
  • Format: c1.nonce.ciphertext.
  • The key is a random 256-bit key generated on your computer and stored in the keychain; it is not derived from your password.
  • Recovery key (format CSR-XXXXX-…) shown only once.
  • Linking computers: ephemeral X25519 + HKDF-SHA256, with a verification code checked out of band.
  • Limit: about 650 KB per account (encrypted blob under 880,000 bytes).

05Firestore rules

Each user can only read, write and delete their own document, only with the fields blob and updatedAt, and the blob must be under 900,000 characters. Everything else is denied.

06Known limitations

  • Local data is not encrypted (see above).
  • Revoking a linked computer is not yet implemented.
  • There is no built-in two-factor authentication (2FA); it depends on what your sign-in provider offers.
  • If you lose the key and all computers, cloud data is unrecoverable.
  • Deleting the account does not delete local data or the local key.
